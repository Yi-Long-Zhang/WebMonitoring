# 安全模型与威胁边界

## 1. 信任边界

```text
客户管理员
  -> 控制面 API
      -> 任务队列
          -> HTTP Worker / Browser Worker
              -> 外部或客户授权目标
      -> PostgreSQL / Object Storage
```

监测目标是潜在恶意输入，不是可信服务。Worker、控制面、数据库和对象存储
之间都必须有明确的身份认证和最小权限。

## 2. 主要威胁

### SSRF 和网络逃逸

风险包括内网地址、回环地址、链路本地地址、云元数据地址、DNS Rebinding、
重定向绕过、非 HTTP 协议、任意端口和超大响应。

必须：

- 只允许明确协议和端口。
- URL 解析、域名解析和实际连接之间复核地址。
- 每次重定向重新执行授权与网络安全校验。
- 阻断 loopback、link-local、private、reserved 和 metadata 地址。
- 限制重定向次数、连接时间、总时间、响应大小和并发数。
- 私网检测只能在客户控制的检测节点和明确网络策略下启用。

### 恶意网页和浏览器逃逸

必须：

- 浏览器运行在隔离容器或沙箱中。
- 禁止访问 Worker 凭据、主机文件、控制面内部接口和云元数据。
- 限制浏览器上下文的存储、下载、弹窗、脚本和网络权限。
- 不把网页内容拼接进系统提示词或高权限工具指令。

### 凭据和敏感数据

- 普通数据库不保存真实密码。
- 登录态检测必须有明确授权并使用 Secret Manager。
- 日志、Trace、错误、截图和模型输入不得包含密码、Token、Cookie、授权头、
  身份证件、个人联系方式和敏感表单值。
- 当前证据下载通过已认证 API 完成租户校验，并在返回前校验对象大小和 SHA-256；
  短时签名 URL 尚未实现。

### 多租户越权

- 所有租户资源查询都必须带租户边界。
- 从 URL、请求头或前端参数中取得的 `tenant_id` 不得直接信任。
- 跨租户管理员权限必须显式建模和审计。
- 证据对象的访问鉴权必须与业务资源一致。

### 证据篡改和不可抵赖

- 原始证据写入后不可更新。
- 保存内容计算摘要并校验对象大小和媒体类型。
- 派生分析引用原始证据 ID、规则版本和分析时间。
- 删除和保留期变更必须有授权和审计。

## 3. 权限模型

推荐 RBAC，权限粒度至少包括：

```text
asset:read / asset:write / asset:delete
monitor:run / monitor:write
baseline:approve / baseline:retire
incident:read / incident:assign / incident:close
evidence:read / evidence:export / evidence:delete
integration:read / integration:write
admin:tenant / admin:user / audit:read
```

高风险权限应支持二次确认或双人审批。UI 隐藏不能代替后端权限校验。

## 4. 数据分类和留存

| 类别 | 示例 | 默认策略 |
| --- | --- | --- |
| 公开页面数据 | 页面标题、公开正文 | 按租户策略留存 |
| 安全证据 | HTML、截图、资源清单 | 不可覆盖，按策略留存 |
| 配置数据 | 资产、规则、基线元数据 | 版本化和审计 |
| 敏感凭据 | 密码、Cookie、Token | 不进普通库、日志和模型 |
| 审计数据 | 登录、变更、处置操作 | 不可静默修改 |

实际留存期限由合同、法规和租户策略确定。代码不得假设所有证据永久保存。

## 5. 告警和外部通知

- 证据写入成功后才发送正式告警。
- 通知内容只包含最小必要信息，不直接嵌入敏感原文。
- 渠道失败应重试并记录最终失败，不阻塞事件落库。
- Webhook 必须签名、限速和防重放。
- 当前 Webhook 签名覆盖 UTC Unix 时间戳和请求体，接收方仍需实现时间窗口
  校验和去重；限速策略尚未独立实现。
- 通知去重键必须与事件去重策略一致。

## 6. 安全测试要求

必须覆盖：

- SSRF 地址、DNS 变化、重定向和端口边界。
- 租户越权读取和写入。
- 恶意 HTML、脚本、URL 和文件名。
- 证据下载过期、越权和内容类型伪造。
- 队列重复消费、超时、死信和告警重试。
- 日志脱敏和错误响应。

## 7. 安全事件处理

发生平台自身安全事件时：

1. 停止扩大影响的任务和通知。
2. 保留相关审计、任务和证据。
3. 标记受影响租户、资产和时间范围。
4. 由人工确认是否暂停相关 Worker 或凭据。
5. 记录修复、验证和复盘结果。

## 8. 安全边界声明

本系统用于经授权的完整性监测和防御性分析。任何绕过认证、漏洞利用、
密码破解、隐蔽扫描和未授权目标探测都不属于产品能力。
