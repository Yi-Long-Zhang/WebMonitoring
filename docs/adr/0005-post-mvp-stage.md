# ADR-0005：阶段口径——从「MVP 建设阶段」到「投产前验证与按场景投产」

状态：Accepted
日期：2026-09-23

## 背景

`AGENTS.md` 0.3.0 称「项目当前处于 MVP 建设阶段」，但这一表述已不再准确，
且各文件口径分裂：

- `AGENTS.md:15`、`CLAUDE.md:3` 说「MVP **建设**阶段」（进行中）；
- `docs/engineering.md:5` 说「MVP **可运行**、补齐安全边界」（已过建设期）；
- `docs/product-scope.md` 的七条 MVP 验收标准截至 2026-09 已全部满足
  （Compose 验收、100 资产压测、多副本演练、备份恢复演练均实测通过，
  见 `docs/operations.md` 验收清单）；
- 两份入口文件 `README.md` 与 `docs/README.md` 事实上已弃用「MVP」一词，
  改用「功能闭环能用，生产上线看场景」的口径。

剩余未完成项（外部 S3 实机演练、rewrap 真实数据执行、资源级授权、双人审批、
外部 KMS、Kubernetes）都是**按场景才需要**的投产前验证或明确的范围边界，
不是「MVP 建设」的未完事项。继续自称「MVP 建设阶段」会让读者低估当前
完成度，也让「还要做什么」变得模糊。

## 决策

1. 阶段表述统一为：**功能闭环已完成，当前处于投产前验证与按场景投产阶段**。
   这是把两份入口文件的事实口径回填到上游文件，不是造新词。
2. `AGENTS.md` 第三节标题「MVP 必须包含」改为「功能基线（已交付）」，
   「MVP 明确不包含」改为「当前明确不包含」；清单内容不变——它们是范围
   边界，与阶段命名无关，继续有效。
3. `AGENTS.md` 版本号 `0.3.0` → `0.4.0`（minor bump：阶段定义是实质内容
   变化，影响所有 Agent 对优先级的理解；修宪规则只要求更新版本号，未定义
   语义版本规则，bump 粒度由本 ADR 说明）。
4. ADR-0001、ADR-0002 标题与正文中的「MVP」是历史决策语境，不追溯修改。
5. `CLAUDE.md`、`docs/engineering.md`、`docs/architecture.md`、
   `docs/product-scope.md` 的阶段表述同口径同步。

## 影响

- 无代码、接口、数据模型影响；纯文档口径变化。
- 「能用什么/不能用什么」的表述不变，仍以 `docs/product-scope.md` 的边界
  声明和 `docs/README.md` 的状态词表为准。
- 后续描述阶段时一律使用新口径；新增文档不得再称「MVP 建设阶段」。

## 迁移方式

无需迁移。引用旧表述的外部材料（如有）按新口径理解即可；本仓库内旧表述
已在同一提交中清扫，仅剩 ADR-0001/0002 的历史语境。
