# ADR-0003: Branch-First Development

- 状态：已接受
- 日期：2026-09-13
- 决策者：项目维护者

## 背景

跨模块功能直接在 `main` 上开发或提交，会绕过开发分支边界，增加用户改动、
试错提交和未完成变更进入集成基线的风险。当前宪法虽然规定了分支规范，但
没有把“首次编辑前检查分支”和“提交前再次核对分支”定义为硬性步骤。

## 决策

除文档、只读分析和用户明确指定直接操作目标分支外，Agent 在首次编辑前必须：

1. 检查当前分支。
2. 若处于 `main` 或其他保护分支，创建并切换到目标明确的开发分支。
3. 默认使用 `codex/<topic>` 命名，主题使用小写英文和短横线。

功能提交只能在该开发分支上创建。提交前必须再次核对分支。Agent 不得因为
用户未指定目标分支、工作区干净或计划后续整理历史而跳过该步骤。未经用户
明确要求，不自动合并到 `main`、删除分支或推送远程。

## 影响

- 功能开发保留清晰的分支边界，便于评审、回滚和选择性合并。
- 小范围文档修订和只读任务不被强制创建分支。
- 已存在的错误历史不自动重写，避免未经授权改变共享提交历史。
- 后续任务必须把分支检查作为工作协议的第一阶段，而不是提交前补救。

## 迁移与验证

本次同步更新根目录 `AGENTS.md` 至 `0.3.0`，加入修改日期和分支前置检查。
后续任务开始时检查 `git branch --show-current`；提交前检查当前分支和
`git diff --cached --name-status`，确认提交不在 `main` 且不包含无关文件。
