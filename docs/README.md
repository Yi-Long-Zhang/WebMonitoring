# WebMonitoring 项目文档

本文是文档入口。用问答形式说明：这个项目现在处于什么状态、文档怎么找、
以及**哪些事它现在不做**。

---

## 现在到了什么阶段？

**Q：这个项目能投产了吗？**

分两件事看，不要混：

- **功能闭环：可以。** 登录 → 登记资产 → 完成所有权验证 → 启用检测 → 审批基线 →
  出差异事件 → 看证据/通知/审计，这条链路已实机跑通（含控制台 Playwright E2E、
  100 资产跨租户压测、多副本演练、备份恢复演练）。
- **生产上线：取决于你的场景。** 见下面的"谁不该用"。

**Q：什么场景现在就能上？**

内网或私有化部署、**单租户或少量可信租户**、给运维/安全团队内部使用。这个范围内
当前能力是够的。

**Q：什么场景现在还不能上？**

- **多租户 SaaS**：没有资源级授权，同租户内任何 ADMIN 能读写全部资源。
- **强合规/审计隔离场景**：没有双人审批，主密钥明文进环境变量，未接外部 KMS。
- **依赖外部 S3 的场景**：外部对象存储实机演练尚未执行。

这三条都是**缺件**而不是缺陷——减配是设计选择，不是 bug。

## 状态用语是什么意思？

文档里描述功能状态时用这三个词：

- **已实现**：代码、接口和自动化测试已经覆盖，仍需按发布门禁验证部署环境。
- **部分实现**：主流程可运行，但存在明确的范围、环境或安全限制。
- **规划中**：产品或架构目标，当前代码不应被视为已经提供。

**默认不标即已实现。** 部分实现、规划中、尚未执行的能力必须在功能描述处
就地显式标注，统一格式：`状态：<档位> —— <具体缺口>`。「尚未执行」不作为
独立档位，只作「部分实现」的限定语。整文描述单次演练的档案
（如 [object-storage-rehearsal.md](object-storage-rehearsal.md)）可以在
文件头标注整体状态。

**Q：看到"已实现"就等于生产可用吗？**

不等于。通过本地内存模式不能推出生产可用性；发布前必须单独完成 Compose、
数据库迁移、队列恢复和安全验收。

## 这些事它现在不做

下面是**产品与部署边界**，不是待办清单。凡在此范围内的能力，本产品当前不提供，
也不应被期待。如果你需要其中某一项，说明当前版本不适用于你的场景。
完整问答（含理由与细节）见 [product-scope.md](product-scope.md) 的
「当前明确不做」。

- **资源级授权与双人审批**：当前不提供。角色只有 ADMIN / OPERATOR /
  AUDITOR / SUPER_ADMIN 四种，按端点做粗粒度校验；**同一租户内 ADMIN 能读写
  该租户全部资源**。
- **多租户运营**：当前不提供。无配额计费，租户只能由 SUPER_ADMIN 创建，
  无跨租户管理员视图。
- **外部 KMS/Vault**：当前未接入。主密钥以明文环境变量注入。
  `状态：部分实现 —— 版本化轮换与存量密文再加密扫描已实现，再加密尚未在真实数据执行。`
- **Kubernetes**：当前只有单机 Docker Compose，无 K8s 清单与 Helm chart。
- **外部对象存储**：`状态：部分实现 —— MinIO 已实测跑通，外部 S3 演练尚未执行`
  （方案见 [object-storage-rehearsal.md](object-storage-rehearsal.md)）。

## 已具备的能力（速览）

- Go 控制面、Go HTTP 检测 Worker、Playwright 浏览器 Worker 和 Vue 控制台。
- 多租户按 slug 登录、SUPER_ADMIN 平台管理员、站点/租户 CRUD 与租户级隔离；
  站点被资产引用时删除失败关闭（`409 SITE_NOT_EMPTY`）。
- 资产登记、负责人、三种所有权验证、启停控制、暂停/恢复和监测策略。
- HTTP/浏览器检测、SSRF 防护、响应和渲染大小限制、重定向复核及行为记录。
- 候选基线、批准/拒绝/废弃、差异信号、事件聚合、处置状态机和审计记录。
  同一指纹恒一行事件：已关闭/误报的问题复现时**重开原事件**（`REOPENED`），
  不插重复行；已恢复（`RESOLVED`）不在重开范围。
- 事件时间线（`incident_events`，append-only）：每轮复现各自的信号集、状态流转、
  负责人变更和备注。事件行上的 `signals` 每轮被覆盖，复现明细只存在于时间线里。
  时间线条目随事件生命周期，**不参与保留期清理**。
- HTML、快照和截图证据保存；下载和报告导出校验大小及 SHA-256；短时签名证据 URL。
- Webhook/企业微信/DingTalk/邮件通知、投递记录和事件级去重。
- 登录防爆破与账户锁定、Redis 会话持久化、用户/角色管理、keyset 真分页、
  任务取消/超时终态、优雅停机和批量导入/导出。
- 登录态检测（HTTP 与浏览器两条路径），凭据 AES-GCM 加密、两侧 SSRF 复核。
- 内存/本地证据开发模式，以及 PostgreSQL、Redis、MinIO 的 Compose 路径。
- 生产配置门禁、90 天证据/365 天审计保留策略、dry-run 清理和备份恢复校验脚本。
- 可重复的验收演练脚本（Compose smoke、100 资产压测、多副本演练、备份恢复）。
- OpenTelemetry Trace（env 门控、默认 no-op）与单元/集成测试。
- 出站告警的配额与熔断（`internal/notifygate`）、通用请求限速、CORS 与 HSTS，
  以及带 `method`/`status`/`path` 标签的请求级指标（路径按集合归并，
  签名令牌不进入标签）。
- Repository 错误传播、真实 PostgreSQL/Redis 集成测试和 100 资产调度合成测试。

## 已经实测过什么？

截至 2026-09-20，以下演练全部实测通过（脚本、关键断言、结果与专项档案见
验收总账 [rehearsals.md](rehearsals.md)）：

- **多副本（HA）**（2026-09-20）：`--scale api=2 --scale http-worker=3`，
  40 资产 40 任务、0 重复分组。
- **100 资产浏览器压测**（2026-09-20）：100 个 BROWSER 任务全部成功、
  500 条证据、85.2 秒、1.17 任务/秒。
- **单机 Compose 验收**（2026-09-15）：smoke 含登录锁定/keyset 分页/
  暂停恢复/任务取消/控制台 E2E。
- **100 资产 HTTP 压测**（2026-09-15）：吞吐 32.8 任务/秒（下限 1.0），
  0 假阳性事件。
- **备份恢复**（2026-09-15）：1198 个受校验文件全部通过，冷启动恢复约
  7 分钟。

外部对象存储（S3）演练**尚未执行**，方案见
[object-storage-rehearsal.md](object-storage-rehearsal.md)。

## 文档写作规则

- `AGENTS.md` 是最高级项目级 Agent 规则，只放不可妥协约束。
- `docs/` 说明如何执行，不得降低 `AGENTS.md` 的安全要求。
- 代码行为改变时，同一提交应更新受影响的文档。
- 重大技术、数据模型和安全边界变化必须新增或更新 ADR。
- 事实、决定、假设和待确认事项必须明确区分。
